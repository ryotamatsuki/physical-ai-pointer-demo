# 卓上フィジカルAI：学習作業なしのスターター

まず START_HERE.html を開いてください。Windows向けの番号付き起動ファイルを用意しています。

## 何ができるか

カメラで実物を見て、既存の学習済みAIで種類や位置を認識し、紙の矢印をサーボで動かします。
画像の収集、ラベル付け、AIの追加学習、学習用GPUは不要です。
AIはノートPCのCPUで動きます。Pico Hはモーター制御を担当します。

- meter：ボトル → LEFT、カップ → CENTER、バナナ → RIGHT。1個ずつ見せる。
- locate：選んだ物がカメラ画像の左・中央・右のどこにあるかを見て、その位置を指す。
- vlm_demo.py（発展）：日本語の指示と画像を外部の画像対応AIに送り、3か所から1つを選ぶ。学習不要だがAPIキー、インターネット、利用枠・料金の確認が必要。

最初は meter を使います。これはごみ素材の判定器ではありません。標準モデルにない「缶・ペン・ティッシュ」の区別は、ローカル版では行いません。
追加学習を避けるため、最初の実演物をボトル・カップ・バナナに変更しています。
locate は3つの決めた位置を指すデモです。任意の三次元位置へ手を伸ばすロボットではありません。

## 入っているもの

- models/：学習済みYOLOX-sの取得元URLとSHA256を記録。00_install.batがモデルを自動取得して検証。
- demo.py / detector.py / control.py：PC側の認識・判断。
- serial_link.py：USB通信。
- pico/main.py / pico/protocol.py：Pico側のサーボ制御。
- config.json：カメラ番号、対象物、角度の設定。
- vlm_demo.py：日本語指示を使う発展版。
- download_examples.py：小さな教材データCOCO8を取得する任意ツール。
- DATASETS.md：既存データセットの使い分け。
- tests/ / VERIFICATION.md：検証と実機で残る確認事項。

## 1. PCだけで動かす：購入・配線より先に確認できる

Windows 10/11、Python 3.12の64bit版を基本とします。作成環境はPython 3.12/Linuxです。
Windowsの起動ファイルや実機カメラの組み合わせは、お手元で確認が必要です。

1. ZIPを展開する。短いパス、例 C:\physical_ai_starter に置くと扱いやすい。
2. Python 3.12をインストールする。python.orgのWindows用インストーラーでPython Launcherも入れる。
3. 00_install.bat をダブルクリックする。最初の依存ライブラリ取得にネット接続を使う。
4. 01_camera_setup.bat を開く。0〜4キーで映像を切り替え、使う映像でSを押して保存する。
5. 04_start_demo.bat を開き、Picoのポート入力では何も入れずEnter。モーターに接続しない試運転になる。
6. カメラに実物のボトル、カップ、バナナを1個ずつ見せる。認識枠と DRY RUN: POINT ... が出ればPC側は動いている。

**EOS RPを使う場合**

- CanonのEOS Webcam Utility Proを導入し、無料の基本機能でカメラ1台をUSB接続する。
- EOS RPは動画モードにし、データ通信対応USB-CケーブルでPCにつなぐ。カメラ側の電池を充電しておく。
- EOS Utility、Zoom、Teamsなど、同じカメラを使うアプリを閉じる。
- Canonの対応OSを確認する。EOS RP対応は確認済みだが、OpenCVから仮想カメラを読めるかはPC環境に依存する。
- 映像が黒い場合はBキーでDirectShow/MSMFを切り替える。それでも読めない場合は内蔵カメラでPC側・配線側の確認を先に進める。
- Canon: https://personal.canon.jp/product/camera/software/webcam-utility-pro

初回導入後、ローカル版はインターネットやAPIキーなしで使えます。モデルとライブラリをローカルに持つ構成です。
COCO画像データ全体をダウンロードする必要はありません。

## 2. 配線する

使用するのは最初に案内した Raspberry Pi Pico H（無線なし・ピン取り付け済み）と通常のSG90です。
SG90-HVなどの「360度連続回転」タイプでは角度指定ができないため、通常の角度制御タイプを使います。

**USBと電池を外した状態で配線する。Pico Hに差し込むのはジャンパー線のメス側。**

| 接続元 | 接続先 | 補足 |
|---|---|---|
| SG90の信号線（通常オレンジ／黄） | PicoのGP15、物理20番ピン | 15番ピンではなくGP15 |
| SG90の電源線（通常赤） | 単3電池3本ケースの＋ | モーター専用電源 |
| SG90のGND線（通常茶／黒） | 電池ケースの− | ミニブレッドボードで分岐 |
| 電池ケースの−と同じ接続点 | PicoのGND、物理23番ピン | GNDを共通にする |
| Picoのmicro-USB端子 | PC | Picoの給電と通信 |
| EOS RPのUSB端子 | PC | 映像取り込み用。PicoのUSBとは別 |

電池ケースの＋をPicoの3V3端子へ接続しない。サーボの電源をGPIOから取らない。
電池は単3アルカリ3本を使う想定です。サーボの配線色は個体の仕様も確認してください。
25穴のブレッドボードは電源の分岐用です。Pico本体を載せる大きさではありません。
ブレッドボードの同一列／同一接点のつながりを確認し、＋と−を別の接続グループに分けます。
電池ケースの先端は端末処理済みリード線を差し込む構成。線が抜けやすい場合は端末を整え、固定してから使用します。

## 3. Picoへプログラムを入れる：最初の1回だけ

1. 電池ケースはOFF。まずサーボの矢印を付けず、PicoだけをUSB接続する。
2. PicoのBOOTSELボタンを押しながらUSBを差すと、RPI-RP2ドライブが出る。
3. https://micropython.org/download/RPI_PICO/ の通常リリースのUF2をダウンロードし、そのドライブへコピーする。
   Pico HはRPI_PICO用。Pico 2やPico W用を選ばない。
4. USBを差し直す。BOOTSELは押さない。
5. 02_copy_to_pico.bat を開き、一覧に出たPicoのポート名、例 COM5 を入力する。
6. pico/protocol.py と pico/main.py がPicoのルートへコピーされる。既存の同名ファイルは置き換わる。
7. USBを抜き差しする。Thonnyやシリアルモニターは閉じる。

Thonnyを使う場合も、2つのファイルをPicoへそれぞれ protocol.py、main.py の名前で保存すればよい。
保存先をPCのフォルダと取り違えないようにする。

## 4. 矢印を取り付けて位置を合わせる

1. SG90を小箱などへ固定する。動かすのは紙の矢印だけ。EOS RPは固定台に置く。
2. 電池ケースをONにし、03_calibrate.bat を開いてPicoのCOMポートを選ぶ。
3. Cと入力して中央へ動かす。動作後に電池をOFFにして、中央方向を向くようにホーンと軽い矢印を取り付ける。
4. 電池をONにしてL/C/Rを確認する。左右が逆なら config.json の angles の left と right を入れ替える。
5. 指針が向く場所に札や物の置き場所を合わせる。locate用の物は、カメラ画像のLEFT/CENTER/RIGHTに対応させる。

初期角度値は40/90/140です。これは制御の目安で、実際の軸角度はSG90の個体やパルス幅で変わります。
書き換える場合は30〜150の範囲にとどめます。引っ掛かる、唸り続ける場合は電池をOFFにして取り付けを調整する。
校正画面では1回の指令後、約2秒でPWM信号が切れます。軽い矢印の位置はそのまま残ることがあります。

## 5. 動かす

04_start_demo.bat を開き、今回はCOMポートを入力する。AI認識に応じて矢印が動きます。

| キー | 操作 |
|---|---|
| Space | 一時停止／再開。停止時はPWM信号OFF |
| M | meterとlocateを切り替え |
| 1 / 2 / 3 | locateで探す物をボトル／カップ／バナナに変更 |
| Q / Esc | 終了 |

meterではカメラに対象を1個ずつ見せます。複数対象や認識なしの場合は新しい動作を決めません。
locateでは対象物を画像の3分割の中央寄りに置きます。境界線付近では指示を保留します。
信頼度0.60以上、複数フレームかつ約0.8秒の安定を見てから動かす設定です。
認識消失が約1.2秒続けばPWM信号を切ります。別の物を突然動かしても、紙の矢印が正しく追従する保証ではありません。
判定が遅い場合は画面の秒/フレームを確認します。古いPCでは応答が遅くなるため、物を静止させて実演してください。

Picoは最後の有効指令から約2秒でPWM信号を切るため、PCの処理やUSB通信が止まった場合も出し続けません。
これは電源遮断ではありません。確実に給電を切る操作は電池ケースのスイッチOFFです。

## コマンドで実行する場合

以下はスターターのフォルダで実行します。Windowsでは python の代わりに .venv\Scripts\python.exe を指定できます。

```text
python tools.py check
python demo.py
python demo.py --port COM5
python demo.py --port COM5 --mode locate --target bottle
python demo.py --camera 1 --backend msmf
```

Mac/Linuxの場合はPython 3.12で仮想環境を作り、requirements.txtをインストールして同じPythonコマンドを使います。
ポート例は /dev/ttyACM0 または /dev/cu.usbmodem... です。OSのシリアル接続権限が必要な場合があります。

## 学習用データも見たいとき：実演には不要

```text
python download_examples.py
python demo.py --image examples/coco8/images/val/000000000036.jpg --output result.jpg
```

COCO8は8枚の小さな動作確認用データです。各画像に今回の3種類が必ず写っているわけではありません。
--image は80種類全体の検出結果を表示します。静止画像モードはモーターを動かしません。
COCO8を追加学習に使う必要はなく、この8枚だけで実用モデルの性能を評価することもできません。
データの使い分けは DATASETS.md を参照してください。

## 発展：日本語で頼んで指さす

このモードも新しい学習・データ収集は不要です。画像対応の学習済み基盤モデルをAPIで使います。
ローカル版の対象外であるペンやティッシュも、モデルが画像から適切に理解できれば選べます。個々の認識精度は事前に確認します。

1. Google AI Studio等でGemini APIキーを用意し、利用できる画像入力対応モデルと利用枠・料金を確認する。
2. 下記を実行する。APIキーの環境変数がなければ、非表示の入力欄で入力できる。
3. カメラの3つの領域へペン・飲料ボトル・ティッシュなどを1個ずつ置く。
4. Spaceを押すと、その瞬間の画像と指示を1回だけ送信する。回答と指針の動作が終わるまで物を動かさない。
5. Sで動作を止め、返答待ちの結果も破棄する。Qで終了する。

```text
python vlm_demo.py --port COM5 --instruction "文字を書く道具を教えて"
python vlm_demo.py --port COM5 --instruction "手を拭くものを教えて"
```

APIモデルの初期値は作成時の公式説明に掲載された gemini-3.8-flash。別の対応モデルは --model MODEL_ID で指定します。
この発展版はカメラ画像を外部APIへ送ります。API呼び出しはSpaceを押したときだけです。ローカル認識版とは別です。
本キット作成時にユーザーのAPIキーは使っておらず、APIの実接続・料金・手元の物での認識は未検証です。

## 職場での3分デモ

1. 「見るのがカメラ、何かを判断するのがAI、動かすのがPicoとモーターです」と説明する。
2. ボトル→カップ→バナナを見せ、画面の認識結果と矢印を同時に見せる。
3. Mでlocateへ切り替え、同じボトルの置き場所だけを変える。
4. 「AIは事前に大量の画像で学習済みです。今日は学習させず、その結果を使っています」と説明する。
5. 「この小さい機械では指針ですが、現場では仕分け板やロボットの腕などに接続する考え方です」とつなぐ。

## 困ったとき

- 接続前にまずPCだけのDRY RUNで映像と認識を確認する。
- 黒い画面：Canonソフト・電池・ケーブル・他アプリ使用中・カメラ番号・backendの順で確認する。
- READY応答がない：MicroPythonの導入、2ファイルの保存先、COMポート、Thonnyの占有を確認する。
- 矢印が動かない：電池スイッチ、GND共通、信号線がGP15であること、DRY RUN表示になっていないかを確認する。
- 誤認識：明るい場所で、対象を大きく写し、背景の対象物を片付ける。confidenceを下げる前に実演条件を整える。
- 矢印が左右逆：config.jsonのleft/right角度を交換し、もう一度校正する。
- 手元PCでの速度や認識率を一律には保証できないため、職場へ持ち込む前に実物3種類で試運転する。
